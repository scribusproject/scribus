# Phase 7: EPUB export

## Architecture checkpoint

The fork had no EPUB exporter or EPUB File-menu command before this phase. `ScribusDoc` exposes document metadata through `documentInfo()`, and text frames contain `StoryText` plus paragraph styles. Those structures support an eventual reading-order extractor, but canvas z-order and page position are **not** a reliable ebook reading order. Linked text frames, groups, inline objects, master-page material, and repeated frame views need explicit handling. PDF and print export are separate paths and remain unchanged.

Scribus already includes a ZIP writer in `scribus/third_party/zip`. Phase 7's first slice reuses it through `EpubExport::writeBook()` in `scribus/epubexport.*`. The writer accepts an explicitly ordered `Book` of plain paragraphs and headings; it does not inspect a Scribus document yet. This keeps serialization independent of layout while reading-order rules are designed and tested.

## First slice and verification

The writer produces a reflowable EPUB 3.3 package with an uncompressed, first-position `mimetype` entry; `META-INF/container.xml`; an OPF package with identifier, title, language, optional creator, modified timestamp, manifest and spine; one XHTML content document; and an XHTML navigation document linked to heading IDs. It escapes XML through Qt's stream writer, rejects invalid XML characters and heading levels, and refuses to overwrite an existing output. Temporary content and the incomplete archive stay in a staging directory beside the requested output until the archive is closed successfully.

`epubexporttests` checks archive entry names, stored `mimetype` ZIP header, XML well-formedness, metadata, heading order, Telugu and special-character round-tripping, bad inputs, missing output directories, and preservation of an existing file. The exporter is compiled into Scribus but has no UI action yet. A standalone synthetic book is not evidence that arbitrary `.sla` files can be exported faithfully.

The synthetic EPUB was also checked with the official EPUBCheck 5.4.0 release: **0 errors and 0 warnings** (the checker reports EPUB 3.4 rules). This validates the sample package, not the future Scribus-document extraction or accessibility of arbitrary books. The checker was downloaded into a temporary directory; no validator binary or proprietary sample was added to the repository.

## Remaining slices

The second slice adds a read-only `EpubDocument::extractSingleStory()` adapter and a separately tested `EpubReadingOrder` policy. It reads the shared story from the first frame of a linked chain exactly once, regardless of document item order, and turns paragraph separators into plain EPUB paragraphs. It reads normal document items rather than master-page items. It refuses to guess across multiple unlinked stories or broken links and refuses grouped, image, table, inline-object, mark, and unsupported control-character content. No File-menu action exposes this partial path yet. This is deliberately narrow: an arbitrary `.sla` still cannot be exported faithfully, and style semantics are not yet mapped.

The third slice adds `EpubDocument::extractStories()` with a caller-supplied order of chain-root text frames. Each root must be present exactly once; missing, duplicate, unknown, or non-root choices fail instead of falling back to canvas order. The existing single-story call still works. The selected pointers are immediate-use API input, not persistent document metadata or a UI control. Tests cover reordering, repeated frame views, incomplete selections, malformed chains, and empty stories. Groups, tables, images, and semantic styling remain unsupported.

The fourth slice stores a 1-based rank as an existing SLA page-item attribute on each story's first text frame. In the Properties Inspector's Attributes section, select a chain-root text frame and set **EPUB reading order**; zero is “Unassigned.” The control is disabled for non-text items, non-root frames, and master-page items. `EpubDocument::extractSavedOrder()` reads the saved ranks and requires all story roots to have unique, contiguous ranks from 1; one unranked story still works. A rank on a non-root frame, malformed value, or incomplete order is an error. Renaming a frame does not affect its rank, because the value belongs to the item, not its name. A save/reopen integration test checks the existing SLA attribute serialization and preservation of an unrelated attribute. This does not yet expose EPUB export, and the inspector currently edits one rank at a time rather than showing a whole-document reorder list.

The fifth slice adds **Manage…** beside the inspector rank. Its modal list shows every printable, normal-page text-chain root with page, name, and a short text preview. Complete saved ranks determine the initial order; otherwise the dialog says clearly that its starting list is only document item order. Move Up/Down changes the preview without changing the document. Only **Assign Displayed Order** writes complete, contiguous ranks; Cancel writes nothing. Batch assignment validates the exact current root set before any write, preserves unrelated attributes, clears stale EPUB ranks from frames that became non-roots, and marks the document changed once. Focused offscreen UI tests cover the starting order, incomplete-rank warning, move buttons, and explicit acceptance. This editor does not claim to order grouped, image, or table content.

The sixth slice traverses nested text-only groups to find linked story roots. It snapshots the item hierarchy, visits each page item only once even if it appears through repeated references, and rejects cycles or missing child references. Master-page and non-printing subtrees stay excluded. The whole-document editor includes grouped text roots, and batch assignment clears stale EPUB ranks on any grouped non-root frames. This does **not** export visual grouping or layout: all non-text content, including images, tables, path text, symbols, and shapes, is now rejected rather than silently omitted. Group child-list order never becomes ebook reading order; saved ranks or an explicit root list still decide story order.

The seventh slice exposes a read-only Scripter `epubReadingOrderPreflight()` query. It reports a stable status, failure detail, and ordered plain-text paragraphs from the current document's saved ranks; it never writes an EPUB or changes the document. The save/reopen integration test now runs this extractor on actual ordinary and nested-grouped `.sla` documents and checks their text order, not only attribute persistence. That test exposed and fixed a recursive snapshot bug: appending to a parent node while `snapshot()` grew the node vector could lose nested children. An actual shape is also checked to fail as unsupported content. This is **not** a complete EPUB preflight: styling, images, accessibility, and navigation are still outside this slice.

The eighth slice begins semantic style mapping. `epubReadingOrderPreflight({"ChapterTitle": 1, "BodyCopy": 0})` now accepts an explicit map from named paragraph styles to paragraphs (0) or heading levels 1–6. The underlying extractor produces heading/paragraph blocks in the saved story order, so the existing EPUB writer can render mapped headings and navigation when export is later exposed. Named styles without a mapping, invalid levels, lists, drop caps, and named character styles fail with a diagnostic rather than silently flattening. The preflight returns `headingLevels` alongside `paragraphs`. Unit tests check the semantic map; an in-app save/reopen fixture checks a real named style, and separate fixtures reject bullets and named character styles. This preserves semantic intent only, **not** visual styling such as font metrics, spacing, colour, local character formatting, or linked assets. There is still no File-menu EPUB export action.

The ninth slice adds explicit named-character-style mappings to `emphasis` and `strong`, for example `epubReadingOrderPreflight({}, {"Emphasis": "emphasis"})`. The document adapter preserves character-style boundaries, the reading-order model coalesces adjacent characters into inline runs, and the writer emits `<em>`/`<strong>` within paragraphs or headings. The preflight result includes `inlineRuns` for inspection. Unmapped named character styles still fail. Mixed-content XHTML is written without pretty-print whitespace, which would otherwise change spaces around inline tags. Unit tests verify mixed runs, XML escaping, and text/run consistency; a save/reopen integration fixture verifies an actual Scribus character style. Direct formatting, nested simultaneous styles, full font/CSS fidelity, lists, and drop caps remain outside this slice. Export is still not exposed in the File menu.

The tenth slice supports flat unordered lists using Scribus's standard bullet character. The adapter recognizes the paragraph's bullet style and skips only Scribus's generated bullet/number mark at the start of that paragraph; EPUB `<ul>` supplies the visual marker instead. The reading-order model marks each list item and starts a new list after intervening prose or a story boundary. The writer emits `<ul><li>…</li></ul>` with inline semantics intact. The read-only preflight reports `blockKinds` and `listStarts`. Unit tests cover list grouping, splitting, escaping, and malformed list metadata; a saved/reopened Scribus fixture verifies two consecutive bullet paragraphs become one list. Numbering, nested lists, custom bullets, and drop caps still fail explicitly. This remains a narrow semantic path, not a general document export command.

The eleventh slice adds flat local-block decimal numbering. Only level-zero `Type_1_2_3` styles with no prefix, a `.` suffix, a positive start value, and no custom restart/other-numbering behavior are admitted; the adapter still rejects global counters, other numeral formats, nested levels, and custom decorations. Scribus-generated number marks are omitted only at the start of a qualifying paragraph. The writer emits `<ol>` and a `start` attribute when the first number is not 1, and the preflight reports `ordered-item` plus `listStartNumbers` on list starts only. Unit tests cover grouping, breaks, non-default starts, and invalid metadata. A generated SLA save/reopen fixture verifies real local numbering starting at 3 and a nested-level rejection. This does not claim complete Scribus numbering parity or expose EPUB export in the File menu.

The twelfth slice admits level-zero local Roman styles (`Type_i_ii_iii` and `Type_I_II_III`) under the same prefix, suffix, and restart restrictions. The writer uses XHTML `<ol type="i">` or `<ol type="I">`, splits adjacent lists when the Roman style changes, and limits each Roman run to values 1–3999, where Scribus and XHTML counters agree. Preflight adds `listTypes`: `1`, `i`, or `I` only on the first item of each ordered list, empty elsewhere. Unit tests cover Roman output, style transitions, and the bound; a saved/reopened SLA fixture checks both Roman styles and rejects an overflowing run. Alphabetic and locale-specific numerals, nested numbering, custom punctuation, and visual CSS remain unsupported.

The thirteenth slice connects the read-only document extractor to the EPUB writer through Scripter's `exportEpubTextOnly(outputPath, identifier, title, language, [paragraphStyles, characterStyles, author])`. Callers provide absolute output paths, publication metadata, and explicit semantic style mappings. The command returns `status` and `detail`; it rejects unsupported document content before writing, and the writer refuses to replace an existing file. This intentionally narrow API does not appear in File > Export and does not claim preservation of visual styling, images, tables, or linked assets. The saved/reopened SLA integration fixture now exports a two-story publication, reads its XHTML and OPF from the resulting ZIP, and checks first-position stored `mimetype`, no-overwrite behavior, missing metadata, explicit heading and Roman mappings, and rejection of an actual shape. The Mac integration test exposed a missing symbol export from the executable to the Scripter plugin; `writeBook()` is now marked with `SCRIBUS_API` for shared-module linkage. EPUB source and header entries were added to the three checked-in MSVC project versions and their filters; the portable project-list check passes. Windows and Linux runtime tests remain pending.

An EPUB copied from that in-app two-story fixture passed the locally available EPUBCheck 5.4.0 release with zero errors and zero warnings (checked against its EPUB 3.4 rule set). This validates the limited text-only sample, not arbitrary Scribus documents or EPUB Accessibility 1.1 conformance.

The fourteenth slice makes the XHTML navigation document follow explicit heading levels instead of flattening every entry into one list. A deeper heading becomes a child of the preceding heading; moving back to the same or a shallower level closes only the necessary lists. Skipped levels do not create empty entries, and a document with no headings still links to the generated book title. A writer test checks exact link order, nested-list depth, skipped levels, and unwinding to a new top-level chapter. A saved/reopened SLA with separate chapter and section styles verifies the in-app Scripter export path, and that EPUB passed EPUBCheck 5.4.0 with zero errors and warnings. This improves the table of contents only; it does not split the one content file into chapter files or solve image/accessibility gaps.

The fifteenth slice splits reflowable content into XHTML spine files at each level-one heading after the first. The initial file retains any pre-chapter text and the first chapter heading, so content is not stranded outside the reading order. Every later top-level chapter starts `chapter-2.xhtml`, `chapter-3.xhtml`, and so on; global heading IDs stay stable, the OPF manifest/spine follows content order, and nested navigation links point to the correct file. Documents with zero or one level-one heading still produce `chapter.xhtml` only. Unit tests cover preface retention, three-chapter boundaries, spine order, and cross-file links. The saved/reopened chapter/section SLA fixture exercises the Scripter path with two spine files; its EPUB passed EPUBCheck 5.4.0 with zero errors and warnings. File splitting does not imply visual layout parity or support for images and tables.

The sixteenth slice supports flat local alphabetic lists when every value stays within A–Z or a–z (1–26). It maps Scribus's `Type_a_b_c` and `Type_A_B_C` formats to XHTML `<ol type="a">` and `<ol type="A">`, preserving the starting value and separating adjacent lists of different types. The 1–26 bound is deliberate: Scribus's sequence algorithm after Z does not match the standard HTML alphabetic counter in all cases, so longer runs still fail preflight instead of changing labels silently. Writer and reading-order tests cover case, transitions, and the bound; saved/reopened SLA fixtures exercise both variants and reject an overflowing run. Nested lists, custom punctuation, and locale-specific numbering remain unsupported.

The seventeenth slice gives each generated XHTML content file a descriptive `<title>` from its first heading. A file with no heading keeps the publication title; the navigation document and OPF also retain the publication title. This helps assistive technology identify the current content document after the previous slice split chapters across files. Unit tests cover escaped headings, preface-plus-chapter files, a first heading below level one, and no-heading fallback; the saved/reopened two-chapter SLA fixture checks both content titles. It does not infer missing chapter semantics or claim full EPUB accessibility conformance.

The eighteenth slice carries each Scribus paragraph's base text direction into XHTML. Right-to-left paragraphs, headings, and list items receive `dir="rtl"`; a list beginning with an RTL item also marks its container, and RTL heading entries in the navigation document receive the direction. LTR remains the XHTML default. The Scripter preflight adds a `directions` array so the result can be inspected before export. Writer and reading-order tests cover mixed directions and invalid metadata; a saved/reopened Hebrew-heading SLA fixture verifies the in-app extraction and exported chapter/navigation markup. This preserves paragraph base direction, not inline bidi isolation, page progression, or all typographic style properties.

The nineteenth slice begins presentation preservation separately from semantic headings: Scribus left, center, right, and justified paragraph alignment become classes in a packaged UTF-8 `styles.css`. The stylesheet is declared in the OPF manifest and linked by each chapter XHTML file. Physical left alignment is made explicit for RTL blocks so it is not reversed by the direction attribute. `epubReadingOrderPreflight()` now reports an `alignments` array. Unit tests cover all four alignments, invalid metadata, CSS packaging, and RTL interaction; a saved/reopened SLA fixture checks centered section text and confirms that Scribus's Extended alignment still fails preflight because its last-line behavior is not reproduced. Fonts, spacing, indents, colours, and arbitrary local formatting remain outside this slice.

The twentieth slice adds an explicit image-block contract to the EPUB package writer. A caller provides already-ordered image blocks, non-empty alt text, and in-memory PNG/JPEG assets; the writer decodes and validates every referenced asset, rejects mismatched media types, bad indices, unused assets, and inline runs on image blocks, then packages generated image names in the OPF manifest. Repeated image references share one asset; images may appear across split chapters. `<figure><img alt="…"></figure>` keeps each image in the supplied flow, and CSS limits its width to the reader viewport. Unit tests exercise both formats, reuse, escaping, corrupt assets, and no-overwrite behavior. This slice does **not** extract Scribus image frames, infer image reading order, or replace the current strict rejection of non-text document content. Decorative images with empty alt text, captions, crop fidelity, colour profiles, and complex anchored positioning need separate semantics and remain unsupported.

The twenty-first slice adds a read-only adapter from one actual, printable, normal-page linked image frame to the writer's `ImageAsset` and image `Block` types. It requires caller-supplied non-empty XML-safe alt text, an available file, and a decodable PNG or JPEG; unsupported frame types, embedded/inline images, and missing files fail explicitly. The Scripter `epubImageFramePreflight(frameName, altText)` exposes status, media type, and byte size without writing the document or an EPUB. An in-app test creates a linked PNG, checks rejection cases, saves/reopens the SLA, and repeats the preflight. This establishes a validated asset boundary only: mixed text/image ranking, persistent alt text, frame crop/colour fidelity, and the actual export command still reject or omit no content silently. The existing `exportEpubTextOnly` remains text-only.

The twenty-second slice stores EPUB image descriptions as a reserved SLA object attribute on normal-page image frames. The Attributes inspector shows **EPUB image description** only for a single selected image frame; editing it saves the value, and clearing it removes the attribute. The new Scripter `setEpubImageAltText(frameName, altText)` provides the same setter, while `epubImageFramePreflight(frameName)` now reads saved alt text when no override is supplied. Invalid XML text and whitespace-only descriptions are rejected; unrelated attributes are preserved. The in-app test checks assignment, invalid edits, missing alt text, clearing, PNG/JPEG preflight, and save/reopen persistence. This is metadata and preflight only: image frames are still rejected by `exportEpubTextOnly`, and mixed-content ordering, image transformation fidelity, and decorative-image semantics are not implemented.

The twenty-third slice adds a neutral mixed-order model, `EpubReadingOrder::extractMixedSavedOrder()`. It treats each linked text chain as one rankable unit and each independent image as one unit. A complete, unique, contiguous rank sequence places images between *whole* text stories; one sole unranked unit remains allowed. The result carries ordered blocks and image assets with stable image indices for the package writer. It rejects ranks on non-root text frames, gaps, duplicates, broken chains, empty/invalid alt text, and missing or unsupported image asset metadata. Model tests cover two stories around an image, two images, image-only content, and failure cases. This does not yet read image ranks from SLA, expose image ranking in the inspector, or enable mixed document export; the existing text-only path remains unchanged. The writer still performs final image-byte decoding and archive validation.

The twenty-fourth slice reuses the existing `scribus:epub-reading-order` SLA attribute for independent, printable image frames. A single selected image frame can now receive a rank through the Attributes inspector's **EPUB reading order** control, or through `setEpubImageReadingOrder(frameName, rank)`; zero removes it. `epubImageFramePreflight()` reports the saved rank. The old text-only **Manage…** action refuses to renumber text stories when a ranked image is present, avoiding accidental rank collisions until a unified editor exists. PNG/JPEG integration tests cover rank assignment, invalid types/values, unrelated-attribute preservation, clearing, and SLA save/reopen. This stores metadata only: it does not infer visual order, resolve rank conflicts automatically, or enable mixed-content export. Users must assign unique contiguous ranks manually for the forthcoming adapter.

The twenty-fifth slice connects the shared rank model to real SLA documents through `EpubDocument::extractMixedSavedOrder()` and a read-only Scripter `epubMixedReadingOrderPreflight()`. Hierarchy scanning now recognizes ordinary image frames while still rejecting unsupported shapes, tables, and malformed groups; the existing text-only adapter explicitly rejects images. The mixed adapter reads each linked text story once, validates each linked PNG/JPEG and saved alt text, and returns ordered text/image blocks plus image assets. Preflight reports block kinds, texts/alt text, image indices, and media types without writing an EPUB. An in-app test verifies text–image–text order across save/reopen, image-only content, rank gaps and collisions, missing alt text, shape rejection, and continued text-only strictness. Mixed-content export and a unified rank editor remain disabled; frame crops, visual geometry, and colour transformations are still not represented in the reflowable output.

The twenty-sixth slice adds a limited Scripter `exportEpubTextAndImages(outputPath, identifier, title, language, [paragraphStyles, characterStyles, author])` command. It exports the saved mixed order using linked PNG/JPEG files and saved image descriptions; it fails on unsupported or incomplete document content and does not overwrite an existing file. The earlier `exportEpubTextOnly()` command remains unchanged. A save/reopen in-app test inspects the EPUB's image bytes, manifest, XHTML sequence and alt text, and covers image-only output plus refusal cases. Successful mixed export reports a fidelity warning: it uses original linked image pixels, not Scribus frame cropping, scaling, geometry or colour adjustments. There is no File-menu export action or unified rank editor yet; a Scripter command is not a claim of general-purpose EPUB export.

The twenty-seventh slice makes **Manage…** a unified reading-order editor. It lists rankable text-chain roots and independent image frames together, including grouped items, with type, page, name, and a short text or saved-image-description preview. A complete shared rank sequence determines the initial order; otherwise the dialog explicitly warns that it starts in document item order. Only **Assign Displayed Order** writes ranks. Assignment rechecks the exact current item set before changing anything, preserves unrelated attributes, and clears stale EPUB ranks from text frames that ceased to be roots or images that ceased to be independent. Dialog tests cover mixed saved order, image labels, moving images, and incomplete-rank fallback. This editor assigns metadata; unsupported shapes/tables, missing image descriptions or links, and image-fidelity limits still cause preflight or export refusal.

The twenty-eighth slice exposes image-fidelity diagnostics through `epubMixedReadingOrderPreflight()["imageFidelityWarnings"]`. Every rankable image frame is identified by name and reports that frame geometry and Scribus colour management are not preserved when the original linked bytes are packaged. Non-default image offset, scale, rotation, flip, and image effects add specific categories. An in-app test changes a linked image offset, saves/reopens the SLA, and confirms the warning remains attached to the same frame; the mixed EPUB export bytes and status remain unchanged. The test also exposed a missing cross-module symbol export on the new shared rankable-item helper; that symbol is now exported for Scripter. These warnings are diagnostic, not a claim that frame transformations have been implemented or that every visual difference can be inferred from frame properties.

The twenty-ninth slice adds optional visible captions to linked image frames without conflating them with required accessibility alt text. **EPUB image caption** in the Attributes inspector and `setEpubImageCaption(frameName, caption)` save a separate SLA attribute; an empty value clears it, and malformed XML text is rejected. `epubImageFramePreflight()` reports the saved caption. The mixed extractor carries captions through the shared reading-order model, and the writer emits an escaped `<figcaption>` after `<img>` only when one is present. Unit tests cover caption propagation, escaping, absent captions, and invalid input; an in-app test verifies save/reopen, clearing, and EPUB XHTML. EPUBCheck accepts the resulting book without warnings. This does not implement styled captions, caption positioning, or decorative-image semantics.

1. Extend other numbered/nested-list semantics only where Scribus counters can be reproduced exactly, then define CSS preservation separately from heading structure. Continue failing on constructs not yet mapped.
2. Define explicit handling for image crops, scaling, colour, styled/positioned captions, and decorative images; continue accessibility checks on representative output.
3. Add an application export dialog and full preflight report only after document extraction is reliable; validate output with EPUBCheck and representative reading systems.
4. Treat fixed-layout EPUB as a separate later track, not a fallback for incomplete reflowable export.

The stable target is the W3C EPUB 3.3 Recommendation and EPUB Accessibility 1.1. EPUB 3.4 is currently a Candidate Recommendation; track it without changing the first slice's conformance target.

The thirtieth slice adds **File > Export > Export Limited EPUB…** for the existing reflowable text-and-linked-image exporter. Its in-app dialog collects publication metadata and an absolute destination, shows the document adapter's blocking preflight result and explicit image-fidelity warnings, and disables export when the document is unsupported or the destination already exists. It rechecks the document before writing. An unsaved document defaults to a new EPUB path in the user's home directory. The File-menu action follows the same enabled state as PDF export when there is no active document. The existing Scripter commands remain available.

A generated mixed-order sample was imported into Apple Books on macOS. The reader's accessibility tree exposed its heading, text before and after the image, image description, and caption in the expected reading order. The reader surface was not capturable for a reliable visual layout comparison, so this is a semantic reader check, not visual fidelity validation. Automated EPUB packaging and extraction tests remain separate. No Windows/Linux reader test was performed in this slice.

This is **not completion of Phase 7**. The dialog presents the first blocking extractor error, not a complete issue-by-issue report. Nested numbering and broader CSS fidelity, image crops/scaling/colour, decorative-image semantics, styled captions, inline images and tables, and fixed-layout EPUB are still unsupported. A separate fixed-layout track must produce selectable text, meaningful reading order, and accessible alternatives, rather than silently rasterizing pages; it needs its own preflight and reader matrix.

The thirty-first slice supports one nested level of Scribus's standard bullet (`•`) within a single text story. The model carries paragraph list depth; the writer keeps the parent `<li>` open around the child `<ul>`, then resumes the outer list. Scripter's text-only preflight exposes `listLevels` alongside its existing list diagnostics. An orphan child, depth beyond one, custom bullet, and nested numbering still fail preflight. Writer and reading-order tests cover the nested structure and rejection cases. A real SLA fixture applies separate outer/inner bullet styles, saves and reopens, then verifies the preflight depths and exported XHTML tree. EPUBCheck 5.4.0 reports zero errors and warnings for that book. Apple Books imports it and exposes the parent, child, and next-parent bullet text in its accessibility tree; the captured reading surface is blank, so visual indentation is not verified there. This does not add nested local counters, deeper lists, visual CSS parity, or a full preflight report.

The thirty-second slice carries resolved paragraph left/right indents, first-line indent, and before/after gaps into reflowable XHTML `style` attributes on paragraphs and headings. Values use points; for RTL blocks, physical left and right margins are swapped to match Scribus's layout handling. Non-finite or extreme values are rejected, and list items with non-default metrics still fail rather than applying paragraph CSS to the wrong list box. Model and writer tests cover propagation, RTL mapping, and rejection. A saved/reopened SLA fixture created with a named paragraph style checks the emitted CSS, and EPUBCheck 5.4.0 reports zero errors and warnings. This preserves selected declared measurements, not pixel-identical appearance: reader styles can override CSS, and fonts, line spacing, colour, tabs, list-specific spacing, and pagination remain outside this slice.

The thirty-third slice makes line-spacing loss explicit rather than adding rigid point-based CSS leading to reflowable text. Baseline-grid paragraphs now block extraction because the page grid is not represented in reflowable EPUB; invalid fixed leading also blocks. A read-only `lineSpacingWarnings` field appears in text-only and mixed Scripter preflight, the limited in-app export dialog shows the same warning, and successful Scripter export details disclose it. Warnings are summarized by the number of printable text stories with fixed leading instead of repeating every paragraph. Saved/reopened SLA fixtures verify that fixed leading warns but exports without `line-height`, while a baseline-grid style rejects export without creating a file. This is an accessibility-conscious limitation, not line-spacing parity: reader-selected text size and spacing remain in control. The rationale follows the [W3C EPUB 3.3 reflowable layout model](https://www.w3.org/TR/epub-33/) and [EPUB Accessibility mapping](https://www.w3.org/TR/epub-a11y-eaa-mapping/).

The thirty-fourth slice adds a read-only, structured preflight report for the limited mixed-content export. The in-app dialog now presents independent metadata, destination, reading-order, linked-image, and line-spacing findings together, with stable issue codes and error/warning severity. It disables export for any error and rechecks immediately before writing. `epubMixedReadingOrderPreflight()` exposes the same document issues as an `issues` list while keeping its existing status and warning fields. An integration fixture confirms that two missing image descriptions and a duplicate rank are all reported in one pass, and that ready content reports fidelity warnings without blocking. This does not yet exhaustively enumerate every deep story-extraction problem: the underlying extractor can still stop at its first unsupported text/content condition. No EPUB package bytes changed in this slice.

The thirty-fifth slice continues the structured report through the text-frame adapter. When separate stories contain unsupported text semantics, preflight now adds a `story-unsupported` error for each affected story, identified by frame name, even though the underlying extraction status still stops at its first failure. The mixed-content integration fixture checks two independently unsupported bullet-style stories in one report. The existing export remains fail-closed and no package bytes change. The report is still not exhaustive within an individual story: multiple errors in one story may collapse to its last adapter diagnostic, and a failed document hierarchy scan may prevent story inspection altogether.

The thirty-sixth slice adds paragraph locations to those story diagnostics. Unsupported paragraph styling is now reported at each affected paragraph, and distinct problems in the same paragraph can appear separately. Inline objects, unsupported marks, and control characters also receive a location when encountered. A regression fixture checks two unsupported paragraphs in one story plus a third in another, while export status stays fail-closed. The extractor still stops scanning an individual story after its first unsupported inline token, and a failed hierarchy scan can still prevent story inspection; this is not an exhaustive whole-document preflight.

The thirty-seventh slice lets the read-only preflight scan continue past unsupported inline tokens to report later problems in the same story. Normal extraction still stops at the first such token and remains fail-closed; no EPUB bytes or accepted-content rules change. A Scribus-generated fixture with multiple line-break control characters in two paragraphs verifies that preflight reports all three with their paragraph locations. Invalid bullet/number marks also continue during diagnostics. A failed hierarchy scan can still prevent text-story inspection, and this does not add support for inline images or tables.

The thirty-eighth slice records each unsupported printable page object found by the hierarchy scan as an `object-unsupported` error with its object name. A read-only preflight can now continue inspecting text stories after ordinary unsupported shapes are found, while the normal extractor still returns the hierarchy error before generating content. A fixture with two shapes and a separately unsupported text story confirms all three findings appear together and export creates no file. Missing or cyclic group references remain invalid-chain errors and still stop traversal, since continuing from a malformed hierarchy could misidentify or duplicate content. No EPUB package bytes change.

The thirty-ninth slice exposes explicit text-style semantics in the in-app limited EPUB export dialog. It lists only named paragraph and character styles actually used by printable text stories. Each paragraph style can be assigned Body or Heading 1–6; each character style can be assigned Emphasis or Strong. Unmapped styles remain blocking, with no guessing from style names. Changing a choice reruns preflight, and export rechecks with the chosen maps immediately before writing. A compact list appears directly in the dialog; long lists scroll. Scripter's mixed preflight also reports the used style names, and saved-document tests confirm unused style definitions are excluded and explicit mappings make styled content ready. A macOS visual check confirmed that the named style appears and the Unmapped state blocks export; accessibility automation could not operate the Qt combo box, so a manual click-through of all choices and Windows/Linux UI testing remain pending. This maps semantics, not full typography or CSS fidelity.

The fortieth slice makes decorative linked images an explicit author choice. A single image frame can be marked **Decorative image** in the Attributes inspector or with Scripter's `setEpubImageDecorative(frameName, True)`; the Boolean flag persists in SLA. The flag requires both the EPUB image description and visible caption to be absent, and while set it prevents either from being added. Preflight reports the flag and accepts an otherwise valid image with no description only when it is marked decorative. The limited reflowable exporter writes an empty `alt` and `role="presentation"` for that image, while ordinary images still require non-empty alt text. Core tests and an in-app save/reopen fixture cover an image-only publication, the emitted XHTML, invalid combinations, and returning to the ordinary missing-alt error after clearing the flag. This is a semantic choice, not automated detection of decorative content. Image crop/colour fidelity, styled captions, inline images and tables, and broader accessibility conformance remain pending.

The forty-first slice adds an opt-in **EPUB image width** control to the Attributes inspector and Scripter's `setEpubImageWidthPercent(frameName, widthPercent)`. Zero (Auto) removes the saved SLA override and leaves existing EPUB output unchanged; 1–100 sets the figure's width as a percentage of the reader's available content area. The image and its optional visible caption remain in the same figure. Preflight reports `widthPercent`, rejects malformed saved values, and the writer validates the range before adding figure CSS. Unit and save/reopen integration tests cover output, clearing, and invalid inputs. This is a reflowable display preference, not a conversion of Scribus's absolute frame dimensions, image crop, rotation, effects, or colour management. Those limitations remain visible in the fidelity warnings.

The forty-second slice adds an opt-in **Use image frame crop in EPUB** choice for linked PNG image frames, also available as Scripter's `setEpubUseImageFrameCrop(frameName, enabled)`. The choice persists in SLA. For a default rectangular frame with positive uniform scale, no rotation, flip, image clipping path, mask, or effects, preflight accepts only a viewport that lands exactly on integer source-pixel boundaries and is fully covered by the PNG. The extractor copies those pixels into a new PNG asset; it never resamples, substitutes a preview image, or silently crops a JPEG. Invalid geometry, unsupported transformations, and malformed saved crop flags block export with an explanation. Unselected frames retain their original linked bytes. A save/reopen integration fixture checks the exact 2×2 exported pixel values from a patterned 4×4 source, unchanged behavior when disabled, and rejection of rotated and JPEG crop requests. This is intentionally narrower than arbitrary Scribus frame rendering: fractional-pixel crops, nonrectangular frames, embedded image effects, colour management, page placement, and other frame appearance remain unsupported.

The forty-third slice lets authors align a visible EPUB image caption independently of its image. **EPUB caption alignment** in the Attributes inspector and Scripter's `setEpubImageCaptionAlignment(frameName, alignment)` offer left (default), center, right, and justify. The choice is stored in SLA only for a frame with a saved caption; clearing that caption also clears its alignment. A non-default choice adds an alignment class to `<figcaption>` using the stylesheet already packaged with each reflowable EPUB. Preflight rejects malformed saved alignment and the writer rejects alignment on a missing caption. Unit and saved-document tests cover XHTML output, persistence, clearing, and invalid combinations. This styles caption alignment only: font, size, colour, caption placement, and full Scribus paragraph-style fidelity remain future work.
